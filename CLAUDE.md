# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

DSGRN (Dynamic Signatures Generated by Regulatory Networks): computes Morse graphs of switching-system models of regulatory networks over a combinatorial parameter graph. A header-only C++ core is exposed to Python through pybind11.

## Build and test

```bash
./install.sh                  # rm -rf build dist; pip install . --force-reinstall --no-deps --no-cache-dir
pip install .                 # first install (pulls install_requires)
pip install '.[MPI]'          # adds mpi4py for the Signatures CLI
pytest tests                  # tests/test_basic.py
pytest tests/test_basic.py::test_build_network
```

- The package is a non-editable install. Any change, C++ or Python, needs a reinstall before `import DSGRN` or the tests see it. A build takes about 1 minute (one translation unit).
- pybind11 is a build-system requirement in `pyproject.toml`. `setup.py` passes CMake `pybind11_DIR` (the build environment's pybind11) and `Python_EXECUTABLE` (the interpreter running pip). Keep `Python_EXECUTABLE` spelled that way: `PYBIND11_FINDPYTHON` uses CMake's FindPython, which ignores `PYTHON_EXECUTABLE` and would otherwise build against whichever Python it finds first.
- There is no CI. Tests run only locally.
- To build a database of Morse graphs for a whole parameter graph: `mpiexec -np N Signatures <network_spec_file> <out.db>` (`src/DSGRN/Signatures.py`).

## Architecture

### C++ core (`src/DSGRN/_dsgrn/`)

- `DSGRN.cpp` is the only translation unit. It includes `include/DSGRN.hpp` and calls one `XBinding(m)` per class inside `PYBIND11_MODULE(_dsgrn, m)`.
- Per-class convention: `X.h` declares the class and ends with an inline `XBinding(py::module&)` holding its pybind11 bindings. `X.hpp` holds the definitions, marked `INLINE_IF_HEADER_ONLY`. State lives behind `std::shared_ptr<X_> data_` (PIMPL), so copies share state. Pickling goes through `stringify()`/`parse()` JSON.
- To add a class: write `X.h` and `X.hpp`, include them in `DSGRN.h`/`DSGRN.hpp`, and call `XBinding(m)` in `DSGRN.cpp`.
- Polymorphism across the binding uses `TypedObject::type()` string dispatch (e.g., `MorseGraph(TypedObject)` branches on `"DomainGraph"` vs. `"MorseDecomposition"`).
- Core pipeline: `Network(spec)` → `ParameterGraph(network)` → `pg.parameter(i)` → `DomainGraph(parameter)` → `MorseDecomposition` → `MorseGraph`. Canonical one-liner: `MorseGraph(DomainGraph(pg.parameter(i)))`.

### Network specification (`Parameter/Network.hpp`)

- `Network(s)` treats `s` as a spec if it contains `:`, otherwise as a filename. Example specs are in `networks/`.
- Line format: `name : logic [: flags]`. Example logic: `(a + ~b)(c)`; `~` marks repression, `+` joins sum terms, and the factors are multiplied. Lines starting with `.` or `@` are skipped.
- Flags: `E` (essential), `B` (Boolean), `M` (multi-Boolean). The default parameter type is DSGRN (`D`).
- Constructor argument `edge_blowup` takes `"neg"` (the default, also used for `""`), `"pos"`, `"all"` or `"none"`. It controls which self-edges are blown up, which changes the out-edge/threshold counts and therefore the parameter graph.

### Parameter graph and logic resources

- `ParameterGraph` loads one file per node from `Resources/logic/`. The filename is `{n_inputs}_{n_outputs}` followed by a suffix:
  - `_{term sizes}` for type `D`, `_B` for Boolean, `_MB` for multi-Boolean;
  - plus `_E` if the node is essential.
  - Zero out-edges count as 1. Each line of the file is a hex code for one logic parameter.
- A missing file raises `Could not find logic resource ...`, meaning that node's input/output/logic combination is unsupported.
- The resource path is set at import time in `__init__.py` (`configuration().set_path(.../Resources)`). The C++ default `/usr/local/share/DSGRN/logic` is only a fallback.
- Parameter indices are mixed-radix. From least significant: one logic-factor digit per node, then one order (out-edge permutation) digit per node. See the comment in `Query/Database.py`.

### Python layer (`src/DSGRN/`)

- `__init__.py` star-imports `_dsgrn` and every Python module, so everything is exposed as flat `DSGRN.*`. A new module must be added there. A new subpackage must also be added to `packages` in `setup.py`.
- `Blowup/` is the exception: it is imported as `from . import Blowup`, not star-imported, and is used as `DSGRN.Blowup.*`. It computes Conley-Morse graphs from a cubical blowup of the phase space with pychomp, including connection matrices and Conley indices. Entry point: `ConleyMorseGraph(parameter)`, which returns `(morse_graph, stg, graded_complex)`. `Blowup.MorseGraph` is a Python function, distinct from the C++ class `DSGRN.MorseGraph`; star-importing `Blowup` would shadow that class.
  - It rebuilds the network with `edge_blowup='none'` and does its own blowup.
  - Its threshold counts must match `Parameter::labelling()`: `max(len(outputs), 1)` per node.
  - It reports unstable Morse nodes (saddles, trivial-index sets) that the C++ `MorseGraph(DomainGraph(p))` does not.
  - Attractor counts agree with the C++ results on networks without self-edges. With self-edges they can differ.
  - It was absorbed from the former external package `DSGRN_utils`.
  - The multivalued maps F_0..F_4 follow the rook fields monograph (`Rook_Field_Paper_v2`), as ported from the vendored `DSGRN_utils` in `bernardorivas/RookFields`. Local copy: `~/Work/projects/rook-fields/code/DSGRN_utils`; the manuscript is in `~/Work/projects/rook-fields/paper/Rook_Field_Paper_v2`.
  - `legacy=True` restores the previous upstream behavior, for reproducing old figures. It is accepted by `CubicalBlowupGraph`, `ConleyMorseGraph`, `save_morse_graph_database_json`, `StabilityQuery`, `IsomorphismQuery` and `ramp_system_wall_labelling`.
  - For DSGRN parameters, the new F_i have differed from legacy only in dimension 3 and higher; no 2D difference has been measured.
  - `ramp_system_wall_labelling` evaluates the outer walls at GB_n (eq:GAB), unlike the RookFields copy, which keeps theta + 10h unless `global_bound` is passed.
  - Not implemented, pending the authors: condition (iii) of `defn:indecisive`.
- The top-level `BlowupGraph.py` module is a separate, older implementation that `Blowup/` does not use.
- `Query/`: queries over the SQLite databases written by `Signatures`. Tables: `Signatures`, `MorseGraphViz`, `MorseGraphVertices`, `MorseGraphEdges`, `MorseGraphAnnotations`, `Network`. `Query.Database` rebuilds the `Network`/`ParameterGraph` from the stored spec.
- `BlowupGraph`, `SubdomainGraph`, `EquilibriumCells` and `SaveDatabaseJSON` build cubical complexes with pychomp. The pip package is `pychomp2`, but it is imported as `pychomp`.
- `ParameterPartialOrders` and `ParameterFromSample` convert between logic-parameter hex codes, threshold partial orders, and sampled parameter values.
- `MorseGraphIsomorphism` uses networkx.

### Other directories

- `Tutorials/` (Jupyter notebooks) is the practical usage documentation. `GettingStarted.ipynb` is the entry point.
- `software/` holds legacy standalone tools with their own CMake/README. They are not built or packaged by `setup.py`.
- `docs/` is an old Sphinx+breathe setup.

## Fork

`origin` is `bernardorivas/DSGRN`, a fork of `marciogameiro/DSGRN`. That repository does the releases and tags; add it as remote `upstream` if missing. It is in turn a fork of `shaunharker/DSGRN`, which has been dormant since 2019.

PyPI wheels are not built from this repository's `setup.py`. They come from a separate private repository, `marciogameiro/DSGRN_Wheels`, which uses its own scikit-build-core configuration.
